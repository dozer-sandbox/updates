Dozer Sandbox 0.32.0

What the agent is doing — and an easier update (issue #223; owner on 0.32.0-rc.4, 2026-10-09: "all pass; ship"). Canary: stable moves on the owner's promote.

  • Agent status (OSC 7501, Mitchell Hashimoto's program-status protocol): deckhold — inside each sandbox, reading every session's output whether or not anyone is attached — answers the agent's support query and keeps its status (working, done, blocked with a kind, error; the spec's limits and validation; a parser fuzz of 20,000 inputs). The host keeps one status watcher per running session (re-opened after a wake). doz ls and doz sessions gain an AGENT column (the most urgent state per sandbox); the dashboard shows it on session tabs, All sessions tiles and a dot on the sidebar's sandbox, and a notice on done / blocked ("needs permission", "has a question", "needs sign-in") / error. Claude Code ≥ 2.1.295 and pi ≥ 1.1.0 report; Codex doesn't yet. The sequences still reach the user's own terminal unchanged. A new VM check (make test-vm-status) drives a fake agent through every state, attached and detached, across sleep and hibernate.
  • doz upgrade [-y] (was doz update, which still works and says so): asks first, -y doesn't; refreshes only Dozer's Homebrew tap first and never leaves Homebrew waiting on its y/n; a check a person asks for goes past the CDN's cached copy of the feed (it was 10 minutes stale after a publish); make publish waits until the live feed lists the release. The notice line and the formula's caveat say doz upgrade -y.
  • doz ui --detach and doz ui stop: the dashboard in the background (log: <store>/ui.log), stopped from any terminal. A doz ui suspended with Ctrl-Z no longer makes later ones hang: they give up after 3 s and name the process and what to do.
  • Release scripts: no cmd | grep -q under pipefail (it failed rc.1's publish on a correctly signed binary).
